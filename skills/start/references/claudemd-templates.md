# CLAUDE.md stack templates

Generate the project CLAUDE.md as: title (`# [Project Name] — Claude Code Instructions`) +
a stack-specific `## Tech Stack` / `## Development` section filled from detection + the
**shared tail** below. For Laravel, prefer the fast path: copy `~/.claude/templates/CLAUDE.md`.

## Shared tail (identical for every stack — our conventions, not derivable)

```markdown
## Workflow

/plan → /plan-review → [clear context] → /plan-approved → /plan-check → /pr → /review → /address-pr → /finish

**Branch flow**: `feat/feature-name → homolog → main`

- Feature branches always target `homolog` (staging)
- `homolog → main` happens via PR after QA — never a direct push

## Testing Rules

**NEVER run the full test suite** — it takes too long and blocks other work.
Always use filtered or targeted tests. Full suite → ask the user to run it in their terminal.

## Commits

Format: `<emoji> <type>: <description>` (present tense, lowercase)
✨ feat · 🐛 fix · 🧪 test · 🧹 chore · 🔍 debug (D-NNNN investigations)

**Never** add AI signatures (`Co-Authored-By`, `Generated by`, etc.)

## Project-Specific Notes

<!-- Add project-specific patterns, architecture decisions, or gotchas here -->
```

## Laravel (fast path: `~/.claude/templates/CLAUDE.md`)

House stack facts the model can't guess: PHP via **Herd Pro** (local URL is
`[project-folder].test`, HTTPS), TALL stack (Tailwind + Alpine + Livewire), MySQL via
Herd Pro, Pest for tests, `./sync-db.sh` syncs production DB to local. Commands are
`herd php artisan …`, not bare `php artisan`. Targeted tests:
`vendor/bin/pest --filter="TestName"` / `vendor/bin/pest tests/Feature/Path/ToTest.php`;
the full suite is the operator's `ptp` alias.

## Other stacks (Next.js, Node, Python, Go, Expo, generic)

Fill `## Tech Stack` (framework, DB/ORM, test runner, package manager) and
`## Development` (local URL + the 4-6 common commands) from what detection found — the
commands themselves are standard for each ecosystem; do not invent tools the repo doesn't
use. Include a **targeted-test** example for the detected runner.

Stack-specific keeps:

- **Expo** — add to Testing Rules: **NEVER mock what you can test** — use real implementations, real AsyncStorage, real factories.
- **Generic / config-only repos** — Testing Rules simplify to: "Always run targeted tests where possible. Full suite → ask the user."
