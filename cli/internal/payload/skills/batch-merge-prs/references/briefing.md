# batch-merge-prs — Detailed briefing

INTENT: take N open PRs from open → verified → merged on the staging branch → linked
issue/backlog closed per merge → full suite handed to the operator. Staging is `homolog` (flow:
`feature/* → homolog → main`) unless the project's CLAUDE.md says otherwise. Run from repo root.

HARD CONSTRAINTS
- **Never merge or push to `main`.** Production ships via the operator's token-gated `/promote`.
- **Guard seam:** an executable `.bravros/guards/pre-merge.sh`, if present, runs before each
  merge; non-zero exit parks that PR for the human. Projects inject their domain gates here.
- **Live-suite safety:** if the operator has a suite running on the tree, server-side merges
  only (`gh pr merge`); defer every `git pull`/`checkout`/local commit until the tree is free.
- **No `--delete-branch` mid-batch** — heads stay recoverable until the batch lands; prune after.
- A `blocked` verdict is a full stop — hand to the operator, never auto-merge it.

FLOW
1. **Verify (parallel, read-only).** `mkdir -p .claude/workflows && cp -f
   ~/.bravros/skills/batch-merge-prs/scripts/verify-prs.js .claude/workflows/` then
   `Workflow({name:'verify-prs', args:{staging_branch, bot:'claude', guards:[…], prs:[…]}})`.
   `bot:'claude'` is load-bearing — the @claude Action posts as bare login `claude`, not
   `claude[bot]`; a bot-suffix filter alone silently matches nothing. Verdicts: clean → queue ·
   needs-changes → one fix-agent per PR (its `blocking[]` only), re-verify · superseded →
   close, never merge · blocked → stop. `deep` mode (checkout + area tests + red-green proof)
   only on a free tree.
2. **Merge (SERIAL, ascending, one standalone call per PR)** under the lock — sequence, flags,
   and the no-`--auto` rule: `skills/shared/merge-flow.md`. Re-check mergeability at each PR's
   turn: the Step-1 snapshot goes stale the moment an earlier sibling merges. Method `--merge`
   unless the repo allows the project's declared alternative (`gh api "repos/{owner}/{repo}"
   -q .allow_squash_merge`). Conflict recovery + per-merge closeout (issue close, backlog
   completion, ff-sync ordering): `references/merge-loop.md`.
3. **Hand off the suite — never deploy.** The full suite runs in the operator's terminal and is
   the real gate: a regression can live outside every PR's changed files. If staging goes red
   after the batch, the batch owns the fix — "another branch broke it" is not a hand-back.

FLEET MODE — a cohort of autogenerated error-fix PRs (KPG-*/BetterStack autofix, "batch merge
all open PRs"): integration-branch flow, park rules, Linear sweep → `references/fleet-batch-verify.md`.

GOTCHA: `gh pr diff` has NO `--stat` — `--name-only`; stats via `gh pr view --json files,additions,deletions`.
On completion (PT-BR, ~20 palavras, nomeie o ramo):
`bravros ha say --force "Mesclagem em lote concluída: <N> revisões publicadas em homologação. Ramo <fragmento>, projeto <repo>." studio >/dev/null 2>&1 || true`
