# Fleet batch-verify → integration branch (KPG-*/BetterStack autofix cohorts)

Use when the ask is "batch merge all the open autofix/error PRs" — a cohort of autogenerated
`🐛 fix:` PRs (branches `fix/<repo>-KPG-*`, a "Jarvis Pre-Review" comment in the body).
Run inside the child repo that owns the PRs (e.g. `paylog/ev`), never a workspace root —
confirm with `git remote -v`. Precedent batch PRs #1153 / #1194: their bodies are the report
template (Merged / Closed won't-do / Parked / Verification / Nits / Tests, "do not squash").

## Authority boundaries

- The flow stages everything on ONE integration branch and STOPS at the staging gate: the
  operator reviews the draft batch PR, runs `ptp` in their own terminal (the real test gate —
  the batch is not "done" until it passes), and merges. Auto-land to staging only on an
  explicit operator grant ("land it"); `main` is never yours.
- **Park for the human — never auto-merge** — anything touching: the afterpay↔ev contract
  (Rule 1), a shared multi-platform/multi-carrier path (Rule 2), fiscal/NF-e gates, postpaid
  ledger timing, physical-only ingestion. A fix must be an ADDED branch in an existing seam,
  never an early-return gate on a shared path — the 1,666-order regression class.
- Closing superseded / won't-do PRs needs the operator's confirmed close authority.

## Flow (order is safety)

1. **Anchor first.** `git checkout -b pre-merge-chain origin/<staging> && git push -u origin
   pre-merge-chain` — integration branch created and pushed BEFORE any code touch.
2. **Adversarial verify (read-only).** Template: `verify-batch-workflow.js` (this dir) — one
   deep verifier + two refute lenses per PR + a barrier merge-planner returning `merge_order`
   / `close_superseded` / `fix_then_merge` / `park` / `needs_human`. Every agent prompt must
   state READ-ONLY (a Bash-enabled subagent once ran `git worktree remove` and destroyed
   work) and must forbid `mcp__mercadolivre__*` (hangs workflows for hours). A backgrounded
   Workflow wraps its return under `.result` — `jq '.result.plan'`, not `jq '.plan'`.
3. **Build.** Merge each green head `--no-ff` in `merge_order`. `.planning/`-only conflicts →
   `--theirs` (base wins; metadata, not code); code conflict → stop and resolve with intent.
   **Never squash the batch PR** — each PR's own merge commit is the Linear/BetterStack
   traceability.
4. **Nits go on the integration branch, never on component heads.** Defer any nit on a
   fiscal / business-fundamental path — an error-fix batch doesn't touch fiscal behavior.
   Targeted test slice: key on changed SOURCE symbols (see `merge-loop.md` § sibling-test
   trap). Pest needs Herd PHP (`intl`) — Homebrew php throws `NumberFormatter not found` on
   money views.
5. **Draft batch PR** to staging, body mirroring the precedent — then stop and hand off
   (PT-BR announce, name the branch).
6. **Component PRs:** close only after `git merge-base --is-ancestor origin/<head>
   origin/pre-merge-chain` proves containment; no `--delete-branch` — keep heads recoverable
   until the batch PR lands (their `--no-ff` commits arrive via the batch merge, closing them
   as MERGED).

## After the batch lands — Linear sweep (workspace `kpgsa`, team `KPG`)

jarvis moves KPG issues to *In Review* on PR-create but never advances them on merge — this
sweep is what lands them in Done:

```bash
~/.claude/scripts/linear-sweep.sh from-batch <batchPR#> --repo <paylog|afterpay> --dry-run
~/.claude/scripts/linear-sweep.sh from-batch <batchPR#> --repo <paylog|afterpay> --cancel "KPG-N KPG-M"
```

Uses `@schpet/linear-cli` (one-time `linear auth login --workspace kpgsa`). Its
`issue comment add` is broken in v2 — state changes only; the PR links carry the context.

## Triggering a missing @claude review

The Action posts as bare login `claude`, not `claude[bot]`. Trigger with a
`@claude review this PR …` comment and require the machine-readable verdict as the FINAL
line, alone, as plain visible text — the Action strips HTML comments, so a wrapped/fenced
sentinel silently disappears:

```
BRAVROS-VERDICT: approved
BRAVROS-VERDICT: changes-requested
```

Per-PR review tallies: use gh's server-side `--jq` — raw comment bodies contain control chars
that crash local JSON parsers.
